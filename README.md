# wifi-monitor

Инструмент вардрайвинга с двойной функцией:

1. **Пассивный сбор данных** о Wi-Fi сетях с GPS-привязкой (Kismet + gpsd) — на выходе
   карта покрытия сигнала вдоль пройденного маршрута.
2. **Проверка работоспособности** собственных точек доступа: подключение, DHCP и реальный
   выход в интернет.

Результат можно выгрузить готовой интерактивной картой в HTML (открывается в браузере,
QGIS не нужен) или сырыми данными для самостоятельного анализа.

## Платформа и оборудование

- Kali Linux x86-64 (VirtualBox / VMware), Python 3.10+
- USB Wi-Fi: Alfa AWUS036AC (RTL8812AU) — **monitor mode**
- USB Wi-Fi: любой managed-адаптер (для проверки своих точек)
- USB GPS: u-blox → `/dev/ttyACM0`

Для режима 3 нужны **две разные карты**: одна физическая карта не может одновременно
быть в monitor и managed режиме.

```bash
python3 -m src.config
```

## Быстрый старт

```bash
# 1. Посмотреть, какие карты видны и какая умеет monitor mode
sudo python3 -m src.cli --list

# 2. Собрать данные 10 минут и сразу получить готовую карту
sudo python3 -m src.cli --mode 1 --duration 600 --export heatmap

# 3. Открыть результат
xdg-open export/heatmap_*.html
```

Без `--mode` запускается интерактивное меню: программа сама спросит режим и карты.
Выбор карт запоминается — со второго раза подхватится автоматически.

## Режимы работы

| Режим | Карты | Что делает |
|-------|-------|------------|
| 1 | 1 (monitor) | Мониторинг: Kismet + GPS, наполнение базы наблюдений |
| 2 | 1 (managed) | Проверка своих точек: подключение и проверка интернета |
| 3 | 2 (mon. + mgd.) | Оба процесса параллельно |

### Как это работает

**Роли карт** привязываются к MAC или USB-пути, а не к имени `wlanN` — оно может
поменяться после переподключения адаптера.

**Координата наблюдения — это позиция оператора**, а не расположение точки доступа.
На каждый пойманный кадр пишется сэмпл «где мы были + какой был сигнал». Из множества
таких сэмплов вдоль маршрута и получается карта покрытия. Замеры прореживаются до одного
в секунду на сеть (GPS всё равно обновляется примерно раз в секунду).

**Без GPS-фикса работа не прерывается**: записи сохраняются без координат (`has_gps=0`),
но в карту и heatmap-экспорты не попадают.

**Проверка точек идёт «по присутствию»** — проверяются только сети, видимые прямо сейчас,
поэтому время не тратится на таймауты отсутствующих. В режиме 2 присутствие определяется
активным сканом клиентской карты, в режиме 3 — пассивно из данных монитора. Повторная
проверка одной точки не чаще, чем раз в `recheck_interval_sec`.

**Подключение к своим точкам идёт по имени сети** — BSSID в конфиге не нужен. Тип
шифрования берётся из `ap_targets.yaml`, а если не указан — определяется из эфира.
К чужим сетям подключений не делается: они только пассивно наблюдаются.

**Режим 3 не отключает NetworkManager целиком** — в `unmanaged` уводится только
монитор-карта, клиентская остаётся управляемой, иначе она не сможет подключаться.

Примеры:

```bash
# полчаса мониторинга + проверка точек параллельно, на выходе карта и Wigle
sudo python3 -m src.cli --mode 3 --monitor AA:BB:CC:DD:EE:FF --client wlan1 \
                        --duration 1800 --export heatmap wigle

# только проверка своих точек, отчёт по статусам
sudo python3 -m src.cli --mode 2 --client wlan1 --export ap_status

# ограничить каналы (быстрее набирается статистика по нужному диапазону)
sudo python3 -m src.cli --mode 1 --channels 1,6,11 --duration 600
```

`--duration 0` (по умолчанию) — работать до `Ctrl+C`.

## Экспорт данных

Экспорт можно запустить вместе со сбором (`--export` у `src.cli`) или отдельно по
уже накопленной базе (`src.exporter`).

| Профиль | Формат | Что внутри |
|---|---|---|
| `heatmap` | HTML | **Готовая интерактивная карта**: сети — переключаемые слои, цвет = сила сигнала. Открывается в браузере |
| `csv` | CSV | Сырые сэмплы одним файлом: `lat,lon,rssi,bssid,ssid,timestamp` |
| `csv_networks` | CSV×N | То же, но **один файл на сеть** + `_manifest.csv` (каталог) |
| `full` | GPKG + CSV | Полный датасет, создаются **оба** файла. `.gpkg` открывается в QGIS перетаскиванием; `.csv` включает записи без GPS |
| `wigle` | CSV | Формат WigleWifi-1.4 для сверки/загрузки на wigle.net |
| `ap_status` | CSV | Результаты проверки своих точек: `ap_id, timestamp, status, rtt, lat, lon` |

Все профили, кроме `ap_status`, берут только наблюдения с координатами.
Файлы складываются в `export/` с меткой времени в имени.

### Фильтры

```bash
# одна сеть по имени — MAC знать не нужно
python3 -m src.exporter --profile heatmap --ssid "MyNet_Garage"

# если одно имя вещают разные точки, экспорт попросит уточнить:
python3 -m src.exporter --profile heatmap --bssid AA:BB:CC:DD:EE:FF

# только за один день (в базе накоплено несколько заездов)
python3 -m src.exporter --profile heatmap --since 2026-07-23 --until 2026-07-23

# сырые данные для QGIS: все сети / отдельными файлами
python3 -m src.exporter --profile csv
python3 -m src.exporter --profile csv_networks

# полный датасет из конкретной базы (создаст .gpkg и .csv)
python3 -m src.exporter --profile full --db data/wifi_monitor.db
```

`--since`/`--until` принимают дату (`YYYY-MM-DD`) или точный момент
(`YYYY-MM-DDTHH:MM:SS`). Обе границы включительно; только дата = весь день целиком.
В `src.cli` те же фильтры называются `--export-ssid`, `--export-bssid`,
`--export-since`, `--export-until`.

Полная справка: `python3 -m src.exporter --help`.

## Конфигурация

### `config/settings.yaml`

Основные параметры. Задавать нужно только то, что меняется — остальное берётся из
встроенных значений по умолчанию.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `db_path` | `data/wifi_monitor.db` | файл базы наблюдений |
| `targets_path` | `config/ap_targets.yaml` | файл своих точек доступа |
| `gps_host` / `gps_port` | `127.0.0.1` / `2947` | адрес gpsd |
| `sync_interval_sec` | `30` | как часто данные Kismet переносятся в базу |
| `heatmap_sample_sec` | `1` | прореживание: 1 сэмпл на N секунд на сеть |
| `presence_window_sec` | `45` | режим 3: окно «сеть видно сейчас» |
| `recheck_interval_sec` | `60` | кулдаун повторной проверки одной точки |
| `scan_interval_sec` | `8` | пауза между циклами присутствия |
| `min_signal_dbm` | `null` | не проверять точки слабее порога |
| `default_security` | `wpa2-psk` | тип шифрования, если не задан и не выведен из эфира |
| `log_level` / `log_file` / `debug` | `INFO` / `data/wifi_monitor.log` / `false` | логирование |
| секция `heatmap:` | см. ниже | тюнинг HTML-карты |

Секция `heatmap:` сливается **по ключам**: можно указать один параметр и не потерять
остальные. Разбор параметров — в [гайде по картам](#гайд-тепловые-карты).

### `config/ap_targets.yaml`

Свои точки доступа. **Права 600, не коммитить** — в нём пароли.

```yaml
defaults:
  check_url: "http://connectivitycheck.gstatic.com/generate_204"
  check_timeout_s: 10
  dhcp_timeout_s: 30

access_points:
  - id: "ap-garage-01"        # человекочитаемый идентификатор
    ssid: "MyNet_Garage"      # имя сети (обязательно)
    psk: "<пароль>"           # пароль ЛИБО psk_hash
    # psk_hash: "5f3c..."     # 64-симв. PSK из wpa_passphrase (предпочтительно)
    # security: "wpa2-psk"    # опц.: open | wpa-psk | wpa2-psk | wpa3-sae | wpa2-eap
    # hidden: false           # опц.: скрытая сеть
    enabled: true
```

Обязательны только `id`, `ssid` и пароль. BSSID не нужен — подключение идёт по имени.
Пароли не попадают ни в логи, ни в экспорт.

```bash
chmod 600 config/ap_targets.yaml
```

Статусы проверки: `ok` — интернет есть; `captive_portal` — перехват портала;
`no_assoc` — не подключились; `no_dhcp` — нет адреса; `no_dns` — не резолвит;
`no_inet` / `timeout` — нет ответа; `eap_unsupported` — для 802.1X одного пароля мало.

## Логирование

Два режима вывода в консоль:

- **обычный** (по умолчанию) — майлстоуны, итоги проверки точек, warnings и errors;
- **debug** (`--debug` или `debug: true`) — полная детальность.

Файл лога (`log_file`) **всегда** пишет полный DEBUG независимо от режима консоли,
поэтому разбирать инцидент постфактум можно без перезапуска.

```bash
sudo python3 -m src.cli --mode 1 --debug
tail -f data/wifi_monitor.log
```

## База данных

SQLite в режиме WAL (позволяет режиму 3 писать из двух потоков одновременно).

| Таблица | Одна строка = | Ключевые поля |
|---|---|---|
| `networks` | уникальная сеть | `bssid`, `ssid`, `encryption`, `channel`, `first_seen`, `last_seen` |
| `observations` | один сэмпл сигнала в точке | `bssid`, `timestamp`, `lat`, `lon`, `rssi`, `has_gps` |
| `ap_health` | одна проверка своей точки | `ap_id`, `timestamp`, `status`, `rtt_ms`, `lat`, `lon` |

Повторные заезды накапливают записи в `observations` — доступна ретроспектива:
когда сеть впервые/последний раз наблюдалась и в каких заездах присутствовала.

# Гайд: тепловые карты

Подробно про профиль `heatmap` — как получить карту, как её читать и что крутить.

## Что это даёт

Один самодостаточный HTML: подложка OpenStreetMap, тепловые слои по каждой сети,
переключатель слоёв и легенда. Открывается двойным кликом, сервер и QGIS не нужны.
Нужен только интернет — подложка тянется из сети, сами слои встроены в файл.

## Рабочий цикл

### Шаг 1. Собрать данные

```bash
sudo python3 -m src.cli --mode 1 --duration 600
```

Важно: карта строится по фактически пройденному маршруту. Чтобы получить осмысленную
картину покрытия, точку нужно обойти/объехать с разных сторон — иначе «горячая» зона
просто повторит линию маршрута.

### Шаг 2. Посмотреть, что накопилось

```bash
python3 -m src.exporter --profile csv
head -5 export/csv_*.csv
```

Или сразу в базе:

```bash
sqlite3 data/wifi_monitor.db \
  "SELECT n.ssid, n.bssid, COUNT(*) c FROM observations o
   JOIN networks n ON n.bssid=o.bssid WHERE o.has_gps=1
   GROUP BY o.bssid ORDER BY c DESC LIMIT 20;"
```

Сеть с числом замеров меньше 20 в карту по умолчанию не попадёт (`min_points`).

### Шаг 3. Построить карту

```bash
# все сети (по умолчанию 10 самых «богатых» замерами)
python3 -m src.exporter --profile heatmap

# одна конкретная сеть
python3 -m src.exporter --profile heatmap --ssid "MyNet_Garage"

# только за нужный день
python3 -m src.exporter --profile heatmap --since 2026-07-23 --until 2026-07-23
```

### Шаг 4. Прочитать карту

- **Цвет.** Красный — сильный сигнал (−30 дБм), зелёный — слабый (−90 дБм). Шкала
  фиксирована, поэтому слои разных сетей сравнимы между собой напрямую.
- **Незакрашенное — это «не измеряли», а не «сигнала нет».** Самое важное отличие,
  см. ниже «Чего карта не говорит».
- **Переключатель слоёв** справа вверху. При открытии включён только первый слой —
  иначе десяток полупрозрачных лент сливается в кашу.
- **Слой «· точки»** (при `show_points: true`) — фактические замеры, при наведении
  показывает RSSI и время. Главный инструмент проверки: тепловая лента обязана лежать
  на цепочке точек.

## Настройка

Все параметры — в секции `heatmap:` файла `config/settings.yaml`. Отдельных CLI-флагов
у них нет: их около двадцати и от запуска к запуску они меняются редко.

| Симптом | Что менять |
|---|---|
| Лента слишком широкая, «мажет» мимо маршрута | `max_distance_m: 5` |
| Лента рвётся там, где шли непрерывно | `bridge_max_m: 60`, `bridge_max_s: 60` |
| Края ступенчатые, хочется детальнее | `grid_step_m: 2` (медленнее, файл крупнее) |
| Пятна «размазаны» между замерами | `idw_power: 3` — вес ближних точек резче |
| Нужной сети нет на карте | `min_points: 5` либо явный `--ssid`/`--bssid` |
| Под картой не видно улиц | `opacity: 0.4` |
| Слоёв слишком много в переключателе | `top: 5` |
| Сеть целиком слабая, выглядит однотонной | `rssi_auto: true` — шкала под факт. диапазон |
| Нужен буфер вокруг точек вместо коридора | `mask_mode: points`, `max_distance_m: 50` |

Полный список параметров с комментариями — прямо в `config/settings.yaml`.

### Коридор вдоль маршрута

Замеры делаются только в точках маршрута, поэтому закрашивать всё в радиусе десятков
метров от них — значит показывать сигнал там, где его никто не мерил. Зона «есть данные»
строится как узкий коридор вдоль фактического трека (`max_distance_m`, по умолчанию ±10 м),
а не как объединение окружностей вокруг точек.

Соседние детекции одной сети могут отстоять на десятки метров (оператор двигался быстро),
поэтому коридор соединяет их «мостами». Мост строится, только если путь между детекциями
не длиннее `bridge_max_m` **и** пауза не больше `bridge_max_s` — временной порог отсекает
склейку разных заездов (одна и та же точка, снятая в разные дни).

### Кластеризация

Одна и та же сеть может встречаться в местах, разнесённых на километры (мобильные точки,
«переезжающие» вместе с оператором). Единая сетка на весь такой охват была бы неподъёмной,
поэтому точки каждой сети разбиваются на пространственные кластеры (`cluster_eps_m`),
и каждый получает свою компактную сетку внутри одного слоя. Кластеры меньше
`min_cluster_points` отбрасываются как GPS-выбросы.

## Чего карта **не** говорит

Здесь легче всего сделать неверный вывод.

1. **Незакрашенная зона ≠ отсутствие сигнала.** Она означает только «сюда не заходили».
   Вывод «за периметр не выходит» по белому полю делать **нельзя** — можно лишь сказать,
   что вдоль пройденного маршрута сигнал был таким-то.
2. **Цвет между замерами — интерполяция, а не измерение.** Реальны только точки из слоя
   `show_points`, остальное посчитано по ним.
3. **RSSI измерен в точке оператора, а не у точки доступа.** Карта показывает, где как
   принимался сигнал, а не где физически стоит передатчик. Это не пеленгация.
4. **Одно устройство может фигурировать как несколько сетей.** При рандомизации MAC
   одна и та же по смыслу сеть станет двумя слоями с суффиксами `(1)`, `(2)`.
5. **Скачки GPS не корректируются.** Одиночные выбросы отсекаются как микрокластеры,
   систематический увод — нет.
6. **Разные заезды смешиваются.** Если нужен один выезд — ограничьте период
   через `--since`/`--until`.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `Нет наблюдений с GPS-координатами` | не было GPS-фикса либо фильтры отсекли всё; проверьте `--since`/`--until` и `python3 -m src.gps_monitor` |
| `Ни одна сеть не прошла отбор` | мало замеров; уменьшите `min_points` или укажите сеть явно |
| Карта пустая, видна только подложка | включён один слой, а вы смотрите не на тот участок — проверьте переключатель и уменьшите масштаб |
| Совсем нет подложки, только пятна | нет интернета, тайлы OSM не загрузились |
| **Плитки не грузятся только в Firefox** (`403 Access blocked`) | OSM требует непустой `Referer`, а Firefox не шлёт его для локальных файлов. Откройте карту через локальный сервер: `python3 -m http.server` в папке `export/` и зайти на `http://localhost:8000/` |
| Лента лежит рядом с дорогой | точность GPS, а не ошибка расчёта; сверьтесь со слоем точек |
| Файл огромный / строится долго | увеличьте `grid_step_m` или уменьшите `top` |
